# VTC 软件接口：方案分析与模型决策

## 1. 范围

本文比较两种让 VTC 应用层软件（ASW，Simulink）与底层软件（BSW，由 `eLSD_Lib` 提供）交换数据的方式。文中记录了 R2020b 模型采用的方案，以及仍未解决的问题。参考头文件为 `20260922更新` 文件夹中的 `eLSD_Lib.h` 和 `eLSD_Lib_ComTypes.h`。

## 2. 头文件中的接口事实

- BSW 只提供函数，没有公开的全局变量。
- 接收路径：`eLSD_Lib_Com_GetRx<MSG>(&snapshot)` 把一条报文复制到调用方的结构体中。每个快照包含 `data` 和 `meta`（在 `eLSD_Lib.h` 中名为 `state`），其中 `meta` 含 `ageMs`、`received`、`expired`。
- 发送路径：`eLSD_Lib_Com_SetTx<MSG>(&data)` 保存应用层的快照，由库周期性发送，调用后不会立即发送。
- 电机路径：`eLSD_Lib_mcIf_set*` / `get*` 函数。用于设置扭矩、转速、位置和限值的 setter 返回 `void`。
- Get 和 Set 通信函数只允许在客户的 5 ms 回调中调用。
- 头文件规定了物理单位：轮速和车速为 km/h，转向角为角度幅值（度）加符号，横摆角速度为 rad/s，离合器扭矩为 Nm，加速踏板开度为 %。

## 3. 方案一：BSW 调用 Simulink 步进函数

应用层的 5 ms 回调负责：把快照复制到生成代码的输入结构体中，调用模型步进函数，再把输出复制回 Set 函数和电机 setter。

```text
eLSD_Lib (BSW) --Get--> 适配层（手写 C） --> 模型输入 Bus
模型步进 (ASW) --> 模型输出 Bus --> 适配层 --Set / mcIf--> eLSD_Lib
```

特点：

- ASW 的输出只取决于其 Bus 输入。它可以在不依赖 BSW 的情况下生成代码、做单元测试和评审。
- 只有适配层依赖库的头文件。
- 适配层只做字段复制。单位换算放在 ASW 内部，使适配层不包含控制逻辑。
- 需要的工作：每组报文定义一个 Bus，以及一个适配层文件。

## 4. 方案二：Simulink 直接调用 BSW 函数

模型中包含封装模块（S-Function，或调用 `coder.ceval` 的 MATLAB Function），由它们调用 Get 和 Set 函数。生成的代码会包含库的头文件并链接库。

特点：

- 不需要手写适配层文件，但封装模块仍需把 C 结构体转换为 Simulink 信号，映射工作量与方案一相同。
- 没有库就无法构建或仿真 ASW。MEX 仿真需要桩（stub），而桩的行为可能与目标库不同。
- BSW 接口变化会迫使模型修改并重新生成代码。
- 需要配置 Custom Code，编写 TLC 文件或使用 `coder.updateBuildInfo`，并在目标平台上验证封装模块。

## 5. 对比

| 议题 | 方案一（采用） | 方案二 |
|---|---|---|
| 结构体到信号的复制位于何处 | 手写 C 适配层 | Simulink 封装模块 |
| ASW 是否依赖 BSW 头文件 | 否 | 是 |
| 不接入 BSW 时能否仿真 ASW | 能 | 需要桩 |
| 配置工作量 | 低 | 高 |
| BSW 接口变化的影响范围 | 仅适配层 | 封装模块和重新生成 |
| 可测试性 | 高 | 中到低 |

决定：采用方案一。

## 6. R2020b 模型决策

1. 模型拆分为两个文件。
   - `VTC_ASW_R2020b.slx`：ASW 边界模型。根输入为 `RxBus` 和 `ExtInBus`，根输出为 `TxBus` 和 `MotorCmdBus`。不含被控对象、场景和 CAN 协议栈，面向 ERT 代码生成。
   - `VTC_TorqueVectoring_R2020b.slx`：MIL 测试台。它模拟场景、CAN 接收路径、VTC-R ECU、整车和后桥，并通过 Model 模块引用 ASW 模型。
2. 基础采样周期为 5 ms（`0.005` s），与 BSW 回调周期一致。旧模型使用 10 ms。
3. 接口 Bus（`Simulink.Bus`，所有元素均为 `single`）由构建脚本定义，并保存到 `VTC_Interface_Buses.mat`。
   - `RxBus`（40 个元素）：ASW 使用的 ECM2、CSA2、ESP2、ESP1、ABS3、ABM2、ABS1、ABS2、BCM6 和 VTC_RR1 字段，每个报文带有 `expired` 标志。
   - `ExtInBus`（4 个元素）：离合器摩擦系数和离合器温度。这两项不在 CAN 头文件中（见第 7 节）。
   - `TxBus`（16 个元素）：VTC_RL1、TOD1 和 ELD1 的字段。`ELD1_Checksum` 是留给适配层的占位符。
   - `MotorCmdBus`（4 个元素）：左电机扭矩、扭矩限值、使能和模式。
4. 边界处的单位保持头文件定义。ASW 的输入调理负责换算：km/h 转 m/s，角度转弧度，轮速转 rad/s。
5. 输入调理从原始报文中推导出控制器所需的信号：
   - 由加速踏板（ECM2，百分比）得到油门；
   - 由 CSA2 得到方向盘转角（角度和符号转换为弧度）；
   - 由 ESP2 得到驾驶模式请求（头文件编码）；
   - 由 BCM6 得到后轴 ELD 请求；
   - 由 ABS3 和 ESP2 得到 ABS 和 ESP 的工作状态；
   - 由 ESP1 得到快速分离请求（`ClutOpenReq = 1`）；
   - 由 ESP2 的 `TAB_Sts` 得到 ESP 许可（待机或工作中）。ESP2 超时时，回退为 2H；
   - 由报文超时和无效状态得到故障标志；
   - 由 VTC_RR1 得到右离合器状态。
6. 输出映射已修正。
   - 右离合器分离请求：正常时为 `RUN = 1`；安全管理器强制分离或后轴断开时为 `FAST_OPEN = 2`。旧模型在强制分离时发送 1，而头文件中 1 表示 `RUN`。
   - AWD 模式在 TOD1（`AWDOperMod`）中发送，不再放在 VTC_RL1 中。旧模型把模式放在 VTC_RL1 中。
   - 模式码 2 至 6 与头文件的 `AwdModeType` 一致（Auto1 至 Auto4、2H）。故障映射为 `SYSTEM_FAULT = 1`。
   - ELD 锁止状态映射到头文件的 `RearLockStateType`。
7. VTC-R ECU 在测试台中模拟，不在被测 ASW 中。测试台在接收路径上加入一个周期的延时，以避免经过模型边界时形成代数环。
8. 已修复的缺陷：场景子系统的输入原本连接到只有一个输入端口的子系统的端口 2，现已改为端口 1。

## 7. 头文件中的缺口（待解决事项）

| 编号 | 缺口 | 影响 | 建议处理方式 |
|---|---|---|---|
| G1 | 没有离合器摩擦系数信号 | 参考值和滑移限值使用标称值 | 由供应商提供，或作为标定量，通过 `ExtIn_MuLeft/Right` 输入 |
| G2 | 没有离合器温度数值（只有告警） | 热管理无法依据 CAN 数据运行 | 通过 `ExtIn_TempLeft/Right` 输入；由 ASW 估算器还是供应商信号提供，待定 |
| G3 | ASW 输入中没有电机反馈 | 滑移和热估算器需要转速和扭矩反馈 | 设计估算器时增加电机反馈 Bus |
| G4 | ELD1 校验和需要明确算法和责任方 | 校验错误会导致报文被拒收 | ASW 提供计数器；由适配层计算校验和 |
| G5 | RX 超时时间未公布 | 超时值是 CAL 中的假设值 | 从 DBC 获取 |
| G6 | 未规定跨报文快照的一致性 | 信号可能来自不同周期 | 记录该假设，并保证同一周期内的数据 |
| G7 | 两个头文件中 `meta` 与 `state` 字段名不同 | 文档或代码出错 | 统一头文件中的命名 |
| G8 | TAB 故障在头文件中编码为 3，在 0922 规范中为 0x4 | ESP 许可判断可能出错 | 与 DBC 责任方确认 |
| G9 | 车轮方向 Stop 在头文件中编码为 3，在规范中为 0x4 | ASW 未使用 | 与 DBC 责任方确认 |
| G10 | ClutOpenReq 值 2（TorqueMaxLimit）没有定义行为 | ASW 未处理 | 与供应商确定行为 |
| G11 | 模式 4H（8）和 4L（9）没有 VTC 行为定义 | ASW 当前映射为 Auto2 | 确认策略 |
| G12 | 缺少自学习和 NVM 接口 | 未建模 | 接口评审后另行处理 |
| G13 | 硬件输入（点火、供电电压）没有接口 | 未建模 | 确认是否需要 |

## 8. 方案二 S-Function 原型

`simulink/scheme2/` 中有一份方案二原型：用 Legacy Code Tool 生成 S-Function，底层通过扁平 C 封装（`eLSD_Sfun_FlatApi.c`）和主机端 `eLSD_Lib` 桩来调用 BSW。该封装仍要把嵌套快照结构体打包成与方案一相同的 40/16/4 浮点向量。详见 `scheme2/README.md`。

这不改变第 5 节的结论：产品路径仍推荐方案一。该原型用于证明：只要接受把结构体映射放进 S-Function 源码，方案二是可以实现的。
