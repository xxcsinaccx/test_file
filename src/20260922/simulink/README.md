# VTC Torque Vectoring Model (R2020b)

Controller-oriented MIL model of the B30 torque vectoring (VTC) system, split
into an application software (ASW) model and a simulation harness. The ASW
boundary follows Scheme One in `Interface_Scheme_Analysis.md`: the basic
software (`eLSD_Lib`) is called from a hand-written adapter in the 5 ms
callback, and the ASW sees only Simulink buses.

## Files

| File | Purpose |
|---|---|
| `build_VTC_TorqueVectoring_R2020b.m` | Builds both models and the interface buses. Run this in MATLAB. |
| `VTC_ASW_R2020b.slx` | ASW boundary model (generated by the script). Target for ERT code generation. |
| `VTC_TorqueVectoring_R2020b.slx` | MIL harness (generated by the script). References the ASW model. |
| `VTC_Interface_Buses.mat` | Simulink.Bus definitions (generated by the script). |
| `Interface_Scheme_Analysis.md` | Comparison of the two interface schemes, decision, and open items. |
| `Interface_Scheme_Analysis_CN.md` | Chinese version of the scheme analysis. |
| `scheme2/` | Scheme Two prototype: Legacy Code Tool S-Functions, host stub, and build scripts. See `scheme2/README.md`. |
| `VTC_TorqueVectoring_R2020b.slx` (previous version) | Replaced when the script runs. It contains the previous single-model structure. |

## Requirements

- MATLAB R2020b with Simulink and Stateflow.
- Embedded Coder is needed only to generate code from `VTC_ASW_R2020b`.
- No other toolboxes are used.

## Build and run

1. Open MATLAB and set the current folder to this `simulink` folder.
2. Run `build_VTC_TorqueVectoring_R2020b`.
3. Open `VTC_TorqueVectoring_R2020b` and run the simulation (stop time 20 s).
4. Select the scenario with `CAL` element `SCN` (1 to 6; default 3).
5. Output: `VTC_LOG` in the workspace (structure with time) and the Scope in
   the `Logging` subsystem.

## Model structure

### VTC_ASW_R2020b (ASW under test)

- Root inputs: `RxBus` (40 elements, header units, with `expired` flags) and
  `ExtInBus` (4 elements: clutch friction and temperature, not in the CAN header).
- Root outputs: `TxBus` (16 elements: VTC_RL1, TOD1, ELD1) and
  `MotorCmdBus` (4 elements: left torque command, torque limit, enable, mode).
- Base sample time 0.005 s (5 ms, the BSW callback period).
- Subsystems:
  - `RX_Select` / `RX_Mux`, `EXT_Select` / `EXT_Mux`: bus to vector.
  - `CAL`: 41 Constant blocks, named by abbreviation.
  - `InputConditioning`: converts header values to controller inputs (km/h to
    m/s, degrees to radians, wheel speed to rad/s) and derives fault flags.
  - `ModeStateManager`, `ReferenceEstimator`, `AWDBaseTorque`, `SlipController`,
    `YawController`, `ELDController`, `SafetyThermalManager`,
    `TorqueArbitration`, `LeftActuator`: control logic.
  - `OutputPacking`: builds `TxBus` and `MotorCmdBus`. Maintains the ELD1
    rolling counter.
  - `TX_Demux` / `TX_Bus`, `MC_Demux` / `MC_Bus`: vector to bus.

### VTC_TorqueVectoring_R2020b (MIL harness)

- `CAL`: same calibrations as the ASW.
- `TestScenarios`: driver and environment scenarios (see the table below).
- `CanRxSim`: produces the `RxBus` values in header units from plant states,
  scenario signals and the VTC-R ECU feedback.
- `ExtSignals`: friction and clutch temperature for `ExtInBus`.
- `VTC_ASW`: Model block referencing `VTC_ASW_R2020b`.
- `CAN_20ms`: 20 ms transmission of VTC_RL1 with dropout control from the scenario.
- `RightECU_Sim`: simulated VTC-R ECU (validation, open request, torque response).
- `VehiclePlant`, `RearAxlePlant`: simplified vehicle and rear axle with clutch
  thermal model.
- `VehicleFeedbackDelay`, `AxleFeedbackDelay`, `RXDelay`: one-cycle delays that
  break algebraic loops through the ASW boundary.
- `Logging`: 5-signal log and scope.

## Scenarios (CAL element `SCN`)

| SCN | Description |
|---|---|
| 1 | Throttle ramp, straight line |
| 2 | Step throttle with low friction on the left side |
| 3 | Throttle step at 0.5 s, steering step at 3 s, SPORT mode (default) |
| 4 | Throttle step at 0.5 s, steering step at 3 s, yaw disturbance at 5 to 6.5 s |
| 5 | Throttle step at 1 s, DEEP_MUD mode (5), rear lock request 1 to 12 s |
| 6 | Throttle step at 0.5 s, steering step at 2 s, CAN dropout at 5 to 8 s |

## Interface mapping (summary)

| Bus element group | Header source | Used by ASW |
|---|---|---|
| `ECM2_*` | `eLSD_Lib_Com_ECM2DataType` (accelerator) | Throttle |
| `CSA2_*` | `eLSD_Lib_Com_CSA2DataType` (steering) | Steering angle |
| `ESP2_*`, `ESP1_*` | ESP driving mode, activity, TAB state, clutch request | Mode, permission, forced open |
| `ABS3_*`, `ABM2_*`, `ABS1_*`, `ABS2_*` | Vehicle speed, yaw rate, wheel speeds | Reference, slip |
| `BCM6_*` | Rear differential lock switch | ELD request |
| `VTC_RR1_*` | VTC-R feedback | Right clutch state and fault |
| `RL1_*`, `TOD1_*`, `ELD1_*` | VTC_RL1, TOD1, ELD1 transmit data | Outputs |
| `MotTorqueCmd`, `MotTorqueLimit`, `MotCtrlEnable`, `MotCtrlMode` | `eLSD_Lib_mcIf_*` setters | Motor command |

Details, including the header enum values used, are in `Interface_Scheme_Analysis.md`.

## Calibrations

All calibrations are Constant blocks in the `CAL` subsystem of both models.
Their values are defined in `addCalSubsystem` in the build script. Values
are engineering assumptions and require test approval.

## Known limitations

- Friction and clutch temperature are not in the CAN header. They enter through
  `ExtInBus` and must be provided by the supplier or by an ASW estimator.
- Motor feedback (speed, torque) is not used by the ASW. It is needed for a
  clutch slip and thermal estimator.
- ELD1 checksum is a placeholder (0). The adapter must compute it.
- Self-learning, NVM and hardware inputs (ignition, supply voltage) are not modelled.
- Header and 0922 specification disagree on TAB failure (3 vs 0x4) and wheel
  direction Stop (3 vs 0x4). The ASW uses the header values.
- Modes 4H and 4L have no VTC behaviour and are mapped to Auto2.
- Simplified physics. For MIL logic verification and calibration studies only,
  not for vehicle release.
